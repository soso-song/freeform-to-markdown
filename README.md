Turn an Apple Freeform board into a searchable, verifiable folder of Markdown, original
attachments, extracted text, spatial relationships, and checksums.

`freeform-to-markdown` is a privacy-first, local-only macOS command-line tool. It reads a
consistent snapshot of Freeform data without modifying the source. Every discovered object is
accounted for as `filed`, `context-only`, `duplicate`, or `unresolved`—nothing is silently
dropped.

> [!IMPORTANT]
> This is an independent, unofficial interoperability project. It is not affiliated with,
> endorsed by, or supported by Apple Inc. Freeform is a trademark of Apple Inc.

## 30-second start

You need macOS, Python 3.11 or newer, and permission to read Freeform's local data. First run the
preflight check:

```bash
uvx --from git+https://github.com/soso-song/freeform-to-markdown@v0.1.0 \
  freeform-to-markdown doctor
```

If macOS reports a permission problem, grant Full Disk Access to the terminal or agent running
the command, then run the check again. List available boards and archive one:

```bash
uvx --from git+https://github.com/soso-song/freeform-to-markdown@v0.1.0 \
  freeform-to-markdown boards

uvx --from git+https://github.com/soso-song/freeform-to-markdown@v0.1.0 \
  freeform-to-markdown archive --board "Example Board" --output ./archives
```

The archive operation above is also a literal one-line command:

```bash
uvx --from git+https://github.com/soso-song/freeform-to-markdown@v0.1.0 ff2md archive --board "Example Board" --output ./archives
```

The archive is ordinary UTF-8 Markdown and files. Search it with any text-search tool:

```bash
rg -i "reservation|receipt|follow-up" ./archives
```

The live SQLite database is never opened. The database and WAL are copied as files only after
before/after stability checks, and only that temporary copy is opened read-only. Referenced
assets are copied without modifying the Freeform source.

## What the archive contains

```text
Example Board/
├── 00 Search Index.md
├── scene-map.yml
├── Board/
│   ├── board-preview.pdf       # optional user-supplied Freeform PDF
│   ├── layout.json
│   └── source-metadata.json
├── Scenes/
├── Originals/
├── Extracted/
└── Manifest/
    ├── archive.json
    ├── objects.jsonl
    ├── assets.jsonl
    ├── relations.jsonl
    ├── exceptions.jsonl
    ├── verification.json
    └── SHA256SUMS
```

- Text and sticky notes become searchable Markdown.
- Images retain their original bytes and receive local OCR sidecars when available.
- PDFs retain their original bytes and receive extracted text; blank text-layer pages attempt local
  OCR when available.
- Link objects retain locally decodable visible text and URL strings; remote cards are not fetched.
- Audio and video retain the original file and local technical metadata. Version 0.1 does not
  transcribe media.
- Shapes, drawings, and groups remain represented as `context-only` layout evidence when they
  carry no searchable content.
- Identical assets are stored once and connected through `duplicate-of` relations.
- Groups, bounds, observed overlaps, conservative proximity, possible-comment candidates, and
  Scene membership are recorded separately from the files they describe.

See [Archive schema](docs/archive-schema.md) for the stable machine-readable contract.

## Commands

| Command | Purpose |
| --- | --- |
| `doctor` | Check permissions, source discovery, schema compatibility, and local OCR support. |
| `boards` | List board titles, stable selectors, object counts, and attachment counts. |
| `archive` | Create a read-only baseline archive for one board. |
| `refine` | Apply a reviewed `scene-map.yml` without duplicating original assets. |
| `verify` | Recheck coverage, hashes, links, privacy findings, and unresolved objects. |
| `install-skill` | Install the bundled Codex/Claude Skill for an agent-guided workflow. |

Run `freeform-to-markdown COMMAND --help` for the complete interface. The shorter `ff2md`
executable is equivalent.

### Preserve an official visual baseline

Freeform's PDF export is optional and is not generated by this tool. Supply one that you exported
from Freeform when exact visual comparison matters:

```bash
ff2md archive --board "Example Board" --output ./archives \
  --board-preview "./Example Board.pdf"
```

The PDF is copied byte-for-byte to `Board/board-preview.pdf`, recorded in source metadata, and
covered by `SHA256SUMS`. Without it, `layout.json` remains the geometric baseline and the archive
records an informational exception.

### Refine the automatic Scenes

Automatic spatial clustering is deterministic, but only a person—or an agent looking at the
board—can confirm that nearby objects belong to the same real-world event. Copy the generated
Scene map, adjust labels or membership, then apply it:

```bash
ff2md refine "./archives/Example Board" --scene-map ./scene-map.yml
ff2md verify "./archives/Example Board"
```

Refinement updates indexes and relationships. It does not rewrite original attachments.

### Use the agent Skill

Install the bundled workflow and then ask your agent to archive a Freeform board:

```bash
uvx --from git+https://github.com/soso-song/freeform-to-markdown@v0.1.0 \
  ff2md install-skill --target codex
```

Use `--target claude` for Claude or `--target both` to share one canonical Skill rather than
maintain two copies. The Skill orchestrates the public CLI; it contains no separate exporter.

## Privacy and safety

- No telemetry, analytics, account login, upload, or cloud AI is used by the core exporter.
- The live database and WAL are copied with stability checks; only the temporary SQLite copy is
  opened, in read-only/query-only mode.
- Asset reads are confined to Freeform's Assets directory; source symlinks are not followed.
- Originals are preserved byte-for-byte and verified with SHA-256.
- Generated Markdown is filtered for common credentials and sensitive URL parameters.
- Unknown schemas, missing blobs, and decode failures become visible errors or `unresolved`
  records.
- Real boards, databases, assets, screenshots, identifiers, and personal data are prohibited in
  this repository and its issue tracker.

Read the full [privacy model](docs/privacy.md) before processing sensitive boards.

## Compatibility and limitations

The first public release has verified fingerprints for Freeform schema `user_version=16`. A
structurally compatible but unrecognized v16 fingerprint is disabled by default and may be used
only with an explicit `--allow-experimental-schema` opt-in on `doctor`, `boards`, or `archive`.
Other versions and schemas missing required columns remain unsupported. See the
[compatibility matrix](docs/compatibility.md).

Freeform does not provide a complete public editable-board export format. This tool preserves
content, original assets, extracted text, object bounds, and known relationships, but cannot
guarantee exact reconstruction of editable layers, drawing strokes, stacking behavior, or every
private application field. The original board should remain the visual source of truth.

## Design references

The project follows established patterns without treating another format as a Freeform parser:

- [MarkItDown](https://github.com/microsoft/markitdown) demonstrates a focused conversion CLI and
  a clear extension model. It is a design reference, not a Freeform parser or project dependency.
- [Docling](https://github.com/docling-project/docling) and
  [Marker](https://github.com/datalab-to/marker) demonstrate structured extraction, OCR pipelines,
  and fixture-driven output evaluation.
- [JSON Canvas](https://github.com/obsidianmd/jsoncanvas) and
  [Excalidraw](https://github.com/excalidraw/excalidraw) demonstrate portable spatial relations and
  open canvas representations.
- [go-freeform](https://github.com/aaronland/go-freeform) extracts images from Freeform's official
  PDF export, while [local-apple-data](https://github.com/BillyBunn/local-apple-data) exposes
  privacy-preserving Freeform metadata. Neither is treated as a raw-board content exporter here.

Freeform's private storage is different from all of these. This project uses its own versioned,
fail-closed adapter and never claims that a lossy folder archive can recreate the editable board.
